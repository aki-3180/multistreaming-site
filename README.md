# MultiView — Twitch / YouTube / Kick

**公開URL: https://multistreaming-site.vercel.app**

複数の配信を1画面で同時視聴できるWebサイトです（[multistre.am](https://multistre.am/) 風）。
各サービス公式の埋め込みプレーヤー・埋め込みチャットを使っているため、**APIキー等の設定は一切不要**。チャット欄から各サービスにログインすれば、そのままコメントも投稿できます。

## 対応プラットフォーム

| サービス | 追加方法 | プレーヤー | チャット |
|---|---|---|---|
| Twitch | チャンネル名 or `twitch.tv/...` URL | ✓（LIVE/オフライン自動判定） | ✓ 表示・投稿 |
| YouTube | 動画/ライブURL（`watch?v=` / `youtu.be` / `live/` / `shorts/`）、チャンネルURL（`/channel/UC…` = 現在のライブを自動再生） | ✓ | ✓ 表示・投稿（動画URL指定時のみ） |
| Kick | `kick.com/...` URL or `kick:名前` | ✓ | ✓ 表示・投稿（`kick.com/popout/<ch>/chat` 埋め込み） |

> Kickの音声切替はプレーヤー再読込方式のため、プレーヤー内の音量操作が確実です。YouTubeの音声はJS API（postMessage）で制御しています。

## 起動方法

Node.js がインストールされていれば、このフォルダで:

```bash
node server.mjs
```

→ ブラウザで **http://localhost:8123** を開く。

> `file://` で index.html を直接開くと Twitch の埋め込みが動きません（埋め込みの `parent` 検証にホスト名が必要なため）。必ずHTTPサーバー経由で開いてください。他の静的サーバー（`npx serve` など）でも動きます。

## 主な機能

| 機能 | 説明 |
|---|---|
| マルチ視聴 | 最大9配信を同時表示。PC・スマホとも常に全配信が1画面に収まるよう自動レイアウト（スクロールなし）。16:9が最大になるよう行列数を自動計算 |
| チャット | チャンネルごとのタブ表示。ログインすればコメント投稿可能。広い画面ではサイドパネル（幅ドラッグ調整可）、狭い画面ではレイアウト内の1枠として表示（縦画面=下部 / 横画面=右側）。別窓ポップアウトも可 |
| 音声ソロ切替 | 追加直後は全ミュート。タイルのスピーカーボタン or 数字キー(1〜9)で「その配信だけ音声ON」 |
| レイアウト | グリッド ⇄ フォーカス（1画面大+帯状サムネイル）切替。タイルの拡大ボタン/ヘッダーのダブルクリックでフォーカス指定。縦画面ではフォーカス時に「大画面上・サムネ下」に自動適応 |
| 並べ替え | タイルのヘッダーをドラッグで配置を入れ替え（マウス・タッチ両対応、タイルが指に追従） |
| URL共有 | `#チャンネル1/チャンネル2` 形式のURLで構成を共有。Twitchは素の名前、他は `yt:動画ID` / `kick:名前` 形式（例: `#shroud/yt:jNQXAC9IVRw/kick:xqc`） |
| 見た目の最適化 | タイルは常に「16:9映像＋ヘッダー」ぴったりのサイズに切り詰めて配置（映像内の黒余白を排除）。狭いタイルでは補助ボタンを自動で間引き |
| 軽量化 | 画質セレクター（`Q`）で解像度を制御。「自動」はスマホでのみタイル実寸に合わせて調整し、PCでは配信側の自動選択に任せる。表示していないチャットは20秒後に解放 |
| スマホ横画面推奨 | 縦持ち時は回転推奨ヒントを表示（タップで全画面＋横画面固定※対応ブラウザ）。横持ちなど低い画面ではツールバーを自動格納し、上部中央のハンドル（▾）で開閉。タイルのバーも普段は隠れ、枠をタップしたときだけ数秒表示 |
| アプリとして使う | PWA対応（ホーム画面に追加でアドレスバー無しの独立起動）。視聴中は画面消灯を抑止、復帰時はプレーヤーを作り直さず再開、構成と音声ソロを自動復元 |
| 誤タップ防止 | タッチ端末では映像を透明なシールドで覆い、枠に触れただけで配信サイトへ飛ぶのを防止。バーの鍵ボタンで一時解除（30秒で自動復帰） |
| プリセット | 現在の構成に名前を付けて保存・呼び出し。前回のセッションは自動復元 |
| 配信状態検知 | オフライン配信は自動でオーバーレイ表示、LIVEバッジ表示 |
| その他 | 全画面表示、プレーヤー再読み込み、Twitchで開く、最近見たチャンネルのサジェスト、モバイル対応 |

## キーボードショートカット

| キー | 動作 |
|---|---|
| `1`〜`9` | 各配信の音声ON/OFF（追加順） |
| `M` | 全体ミュート |
| `C` | チャット表示切替 |
| `G` | グリッド ⇄ フォーカス切替 |
| `F` | 全画面 |
| `Q` | 画質・軽量化の設定 |
| `?` | ヘルプ |

## 端末が熱くなるとき

発熱の主因はメモリではなく**映像のデコード処理**です。スマホが同時に処理できる動画は2〜4本程度で、それを超えるとCPUのソフトウェアデコードに落ちて発熱が跳ね上がります。

- **画質を下げる**（`Q`）— スマホでは「自動」がタイル実寸に合わせて解像度を落とします。「軽量 360p」「最軽量 160p」でさらに軽くなります
- **同時視聴数を減らす** — 最も効果が大きい方法です
- チャットを閉じる（`C`）— 非表示のチャットは自動解放されます

> PCでは「自動」時に画質を制御しません。`setQuality()` は再生を作り直すため、レイアウト変更のたびに呼ぶとTwitchのプリロール広告が繰り返し挿入され、視聴できなくなるためです。PCで固定したい場合は「自動」以外を明示的に選んでください。

## タイルの大きさについて

グリッドは各タイルが16:9を保ったまま最大になる行列数を自動計算します。多くの場合**横幅が制約**になるため、上下に帯状の余白が残ることがありますが、これは幾何学的に映像へ変換できない領域です（16:9のタイルを横長でない画面に並べるため）。

横持ちスマホなど高さの低い画面では、ヘッダーを映像の上に重ねて表示し、タイルを16:9のまま最大化します（ヘッダーが高さを消費しないぶん映像が大きくなる）。

映像を大きくする実効的な方法：

- **ウィンドウを広げる** — 横幅が制約なので最も効きます（例: 4分割で幅1520px→1920pxにすると各映像が751px→951pxに）
- **フォーカスモード**（`G`）— 1つを大きく表示
- **チャットを閉じる**（`C`）

## スマホで「アプリ」として使う

ブラウザのメニューから **「ホーム画面に追加」**（Android は「アプリをインストール」）を選ぶと、
アドレスバーの無い独立したアプリとして起動できます（`manifest.webmanifest` + `sw.js`）。

アプリとして常用するときに効いてくる挙動：

| 挙動 | 内容 |
|---|---|
| 構成の復元 | チャンネル・レイアウト・チャットのタブ・**音声ソロ**を復元。音声は自動再生ブロックを避けるため、最初のタップまで適用を保留します |
| 保存領域の永続化 | `navigator.storage.persist()` を要求し、容量逼迫時に前回の構成が消えるのを防ぎます |
| 画面消灯の抑止 | 視聴中は Screen Wake Lock を取得（対応ブラウザのみ）。画面が消えて復帰するとプレーヤーが作り直され、広告から始まるためです |
| 復帰時の再開 | 他アプリから戻ったとき、プレーヤーを**作り直さず**再開だけします。離脱前に自分で止めていたものは触りません |
| チャットの保持 | ホーム画面から起動しているときは、非表示チャットの解放を20秒→3分に延ばします（破棄＝再読込のたびにログインし直しになるため） |

> **ログインCookieそのものは保存できません。** チャットは各サービスの埋め込みで、Cookieはそれぞれのドメインのものです。
> このサイトのJavaScriptからは読み書きできないため、下の「チャットにログインできないとき」の対処が必要です。

### タッチ操作

映像そのものが配信サイトへのリンクになっているため、タッチ端末では映像を透明なシールドで覆っています。

- 枠をタップしても配信サイトへ飛ばず、**タイルのバーが数秒だけ表示**されます（横持ちではバーは普段隠れています）
- プレーヤー内蔵のボタン（画質・全画面など）を使いたいときは、バーの**鍵ボタン**で一時解除（30秒で自動的に戻ります）
- シールドがあるおかげで、プレーヤー内蔵のミュートとこちらのミュートが二重に効いて状態が食い違う問題も起きません。
  鍵を外して内蔵ボタンを操作した場合も、こちらの表示・ソロ切替が自動で追従します（Twitch はポーリング、YouTube は postMessage で実状態を取得）

## Twitchの広告が毎回流れるとき

Twitchは**再生が止まって再開するたび**にプリロール広告を挿入します。これは配信元の仕組みで、
埋め込み側から消すことも飛ばすこともできません。

アプリを離れると広告が入るのは、**ブラウザが省電力のため無音の動画を一時停止する**ためです。
Chromiumはこの判定を「実効音量（ミュートなら0、それ以外は音量）が0か」で行うので、
ミュートを外して音量0にしても止められます（＝ページ側から回避する手段が実質ありません）。

このアプリでやっていること：

| 対策 | 内容 |
|---|---|
| 画面消灯の抑止 | Screen Wake Lock。アプリを離れなければ広告は入りません |
| 停止させないUI | スピーカーボタン（`1`〜`9` / `M`）は再生を止めないミュート。タッチ端末ではシールドでプレーヤー内蔵の一時停止に触れないようにしています |
| 復帰時のずらし再開 | 音声ONの枠 → 拡大中の枠 → その他 の順に1.2秒ずつずらして再開（同時だと回線を取り合ってどれも進まなくなるため） |
| 作り直さない | 復帰時はプレーヤーを再生成せず `play()` のみ。再生成は必ず広告からになります |

**「バックグラウンドでも止めない（実験的・既定オフ）」** — `Q` の設定パネルから有効にできます。
非可聴の配信を「ミュート」ではなく「音量0.001」で維持し、ブラウザに一時停止させないようにします。

- 通信量と電池を使います。他アプリの音楽が止まることがあります（音声フォーカスを取るため）
- 5分以上バックグラウンドが続くと自動的に解除します
- iOSは `volume` の変更を無視するため無効（そもそもアプリを離れると必ず停止します）
- 音量が反映されない環境では全配信から音が出てしまうため、適用後に実測して効いていなければ自動でオフに戻します

広告を完全に無くすには Twitch Turbo かチャンネルのサブスクリプションが確実です。

## チャットにログインできないとき

埋め込みチャットのログインには **各サービス（twitch.tv / youtube.com / kick.com）のサードパーティCookie** が必要です。
SafariやCookieブロック設定のあるブラウザでは、サイト設定で該当ドメインのCookieを許可してください。

## デプロイ

- **GitHub**: https://github.com/aki-3180/multistreaming-site
- **Vercel**: https://vercel.com/aki-s-projects3180/multistreaming-site （`main` に push すると自動で本番デプロイ）

ビルド不要の静的サイトなので、リポジトリのファイルをそのまま
GitHub Pages・Cloudflare Pages・Netlify 等に置くだけで公開できます。

- **HTTPS必須**（Twitch埋め込みの要件。localhost のみ HTTP 可）
- 埋め込みの `parent` パラメータはページのホスト名から自動設定されるため、ドメインごとの設定変更は不要

更新を公開するには、変更をコミットして `main` に push するだけです（Vercelが自動デプロイします）：

```bash
git add -A
git commit -m "変更内容"
git push
```

## 構成

```
index.html              … ページ構造
styles.css              … スタイル（ダークテーマ）
app.js                  … アプリ本体（プレーヤー管理 / レイアウト計算 / 状態管理）
manifest.webmanifest    … PWA定義（ホーム画面に追加したときの名前・アイコン・表示モード）
sw.js                   … Service Worker（アプリシェルのキャッシュ。配信/チャットは対象外）
icon-*.png              … PWAアイコン（apple-touch-icon.png はiOS用）
server.mjs              … ローカル確認用の静的サーバー（デプロイには不要）
```

## 制限事項

- 視聴者数・ゲームカテゴリ等の表示は Twitch API（要APIキー）が必要なため未実装
- 同時視聴数が多いほどPC負荷が高くなります（1配信ごとにプレーヤーが動くため）
- 本サイトは非公式のファンメイドツールです
